Подготовка к выпуску в Яндекс Игры

Проверено по официальной документации 4 октября 2026 года. Игра в консоли ещё не создана; публичного сервера пока нет. Проект подготовлен, но публикация и платформенные проверки не выполнены.

Что сделано в проекте

  • SDK через относительный /sdk.js, LoadingAPI при загрузке ангара, GameplayAPI, остановка звука и управления при паузах, восстановление соединения.
  • Гостевая игра без обязательного входа. Добровольный вход для облачного токена ангара; сам прогресс хранится на сервере. Оплаты доступны только после успешного сохранения облачного токена.
  • Полноэкранная реклама при явном выходе с результата на главный экран: минимум три завершённых боя и 180 активных секунд. Нет показов во время боя, обучения, ручной паузы, подготовки босса или автоматической смены вылета. Действующий премиум блокирует рекламу. Ошибка/отсутствие рекламы не препятствует выходу.
  • Rewarded-адаптер существует, но рекламные награды не подключены. В первой версии не заявляйте rewarded и не добавляйте кнопки обещанных наград. Sticky-баннеры отключить в консоли: автоматический баннер может конфликтовать с премиумом и полем боя.
  • Подписанные чеки проверяются сервером; начисление сохраняется до consumePurchase. Необработанные покупки проверяются при входе и по кнопке восстановления. Серверный секрет не попадает в клиент.
  • Релизный магазин показывает только товары из действующего SDK-каталога; цена и значок портальной валюты берутся из SDK. Локальный режим сохраняет предложения для разработки.
  • В релизе поле боя занимает всю доступную ширину либо высоту с пропорцией 16:9. Локальный режим сохраняет прежние отступы. Русский — единственный заявляемый язык; прочие языки портала используют русский.
  • Сборка одного игрового входа и ZIP без галереи, исходных промптов, серверных файлов, профилей и секретов; проверка имён и лимита 100 МБ. Подготовлена схема Docker + Caddy с HTTPS/WSS и постоянным хранилищем.

1. Сервер: до загрузки финального ZIP

Архив содержит только клиент. И одиночная кампания, и дуэли требуют сервер: один лишь ZIP без доступного WSS не запустит игру. Выберите Linux-сервер и домен; расходы и договоры пока не оформлены. Для начала используется один экземпляр Node.js с JSON-хранилищем. Не запускайте несколько экземпляров на одном файле: нужна отдельная миграция на БД для масштабирования.

  1. Установите Docker Engine с Compose на Linux, направьте A-запись домена на сервер. Проверьте также AAAA, если она есть. Откройте 80/443, остальные внутренние порты не публикуйте.
  2. Скопируйте репозиторий. В deploy/.env задайте GAME_DOMAIN=ваш.домен.ru. YANDEX_PAYMENT_SECRET пока оставьте пустым: покупки на сервере выключены, реклама работает независимо. После подключения покупок добавьте секрет из консоли; без префикса VITE_.
  3. Создайте каталог и права для пользователя контейнера: mkdir -p deploy/data && sudo chown 1000:1000 deploy/data. Не копируйте локальные debug-профили в боевой ангар.
  4. docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --build. Caddy получит сертификат автоматически при корректных DNS и доступных портах. Debug принудительно выключен в production.
  5. Проверьте https://ваш.домен.ru/ (status ok), соединение wss://ваш.домен.ru/socket из браузера и отсутствие ошибок сертификата. Проверьте сохранение после перезапуска контейнера. Конфигурация подготовлена, но Docker-сборка на этой машине не проверена: Docker Engine не запущен.
  6. До пользователей настройте резервную копию deploy/data/profiles.json на другой носитель и проверьте восстановление. Для гарантированно согласованной копии остановите game, скопируйте файл, затем запустите game. Caddy-хранилище также сохраняйте. При обновлении используйте штатную остановку, а не SIGKILL; сервер сохраняет карьеру при SIGTERM.

2. ZIP для загрузки

В корне проекта выполните npm ci, затем npm test. PowerShell:

$env:VITE_SERVER_URL = 'wss://ваш.домен.ru/socket'
npm run release:yandex

Linux: VITE_SERVER_URL=wss://ваш.домен.ru/socket npm run release:yandex. Результат — release/biplanes-yandex.zip и отчёт рядом. URL вшит в сборку: после смены домена пересоберите. Скрипт запрещает пустой URL, ws, localhost и тестовый .example. Соединение, DNS и CSP проверяются отдельно; скрипт не подтверждает доступность сервера.

Без домена доступен npm run release:draft: biplanes-yandex-LOCAL-DRAFT.zip только для локальной проверки. Не загружать в консоль: он использует локальный сервер. Папка release игнорируется Git. В ZIP нет секретов. Локальные рекламные моки SDK не подтверждают реальные показы и не создают настоящие подписанные серверные оплаты.

3. Консоль Яндекс Игр: до модерации

  1. Создайте аккаунт разработчика и черновик. Заполните обязательные сведения аккаунта и доступные условия монетизации. Выберите отсроченную публикацию, чтобы не выпускать игру автоматически после модерации.
  2. Загрузите финальный ZIP. Укажите альбомную ориентацию и русский язык. Оставьте только реально проверенные платформы; Android/iOS включайте после проверки на физических устройствах. ТВ не заявляйте. Возрастной рейтинг выберите по анкете консоли.
  3. Отметьте облачные сохранения. Во вкладке CSP добавьте домен WSS без протокола, пути, порта и IP. Обоснование: «Авторитетный сервер кампании, дуэлей, постоянного ангара и валидации подписанных покупок». Согласуйте/дождитесь разрешения домена и проверьте запрос из черновика. Все графика и звук поставляются в архиве.
  4. Подключите монетизацию и полноэкранную рекламу в консоли, выполните требуемые платформой условия/договор. Sticky отключите. Не подключайте сторонние рекламные сети. Расписание вызовов уже в коде; пригодность показа определяет SDK.
  5. Товары опциональны для первого выпуска с рекламой. Для покупок получите разрешение платформы, создайте ID premium, gold100, gold300, gold800 из каталога, задайте цены в консоли. Цены не назначены автоматически. Настройте изображения и активность товаров; добавьте серверный секрет и перезапустите game. Не переименовывайте ID уже выпущенных товаров. Если покупки не одобрены, оставьте их выключенными; релизный интерфейс скрывает отсутствующие товары.
  6. Перенесите поля из текстов карточки. Название предложено, при замене согласуйте его с изображениями. Уберите английское описание и автоматические переводы, если они создают впечатление английской версии интерфейса.
  7. Иконка PNG 512×512 и обложка PNG 800×470 — отдельные иллюстрации, не скриншоты. Загрузите настоящие скриншоты и горизонтальное MP4 16:9, высота от 400 px, до 28 секунд и 100 МБ. Медиа не должно обещать несуществующие механики. Видео и снимки с debug-кнопками/тестовыми значениями не публиковать.

Подготовленные материалы: иконка 512×512, обложка 800×470, снимок полёта 1280×720, бой с интерфейсом, главный экран, геймплей MP4 1280×720, 18 секунд. Иконка и обложка созданы по игровому самолёту; видео записано с реальной симуляцией и отрисовкой на изолированной сцене, без изменения пользовательской карьеры. Снимок взят из видео; ролик записывает игровое поле без HTML-панелей. При изменении игры обновите медиа. Дополнительные снимки интерфейса и боёв можно записать перед отправкой.

4. Проверки в черновике — до публикации

Локальные тесты не заменяют эти проверки. Через «Открыть с debug-панелью»:

  • Первый гостевой вход, медленное соединение, LoadingAPI ровно после готового ангара, запуск и остановка GameplayAPI на бое, паузе, результате, смене вкладки и рекламе.
  • Звук выключается при сворачивании и рекламе; закрытие рекламы не снимает ручную/платформенную паузу. Проверить обычный показ, отсутствие показа, ошибку, повторные нажатия и премиум. Для проверки рекламы реально накопить три законченных боя и 180 активных секунд.
  • Портрет → альбом, поворот в бою, тач двумя пальцами, iOS/Android, Full HD/2K/4K, кириллическая раскладка клавиатуры. Нет обрезанных кнопок, выделения/контекстного меню при долгом тапе и системного аудиоплеера.
  • Сохранение после покупки самолёта, награды, выбора модификатора, босса, перезагрузки, сетевого сбоя и перезапуска сервера. Гость сохраняет карьеру на этом браузере; авторизованный игрок возвращает тот же ангар на другом устройстве. Проверить вход в аккаунт с уже существующим облачным ангаром.
  • Для каждого активного товара: отмена и успех оплаты, перезагрузка после оплаты до начисления, сбой диска/сети, восстановление при следующем входе, повторная обработка без двойной выдачи. SDK-значок и цена должны меняться при Currency mock (TST). Премиум: +50% только боевых наград, без рекламы, безлимит боссов, продление, истечение. Успешный платёж консумируется только после сохранения сервером.
  • Второе устройство/вкладка, очередь и бой против живого игрока, бот, повторное подключение. Консоль браузера без необработанных ошибок, заблокированных CSP-запросов и смешанного HTTP/HTTPS.

Сохраните результаты и версии ZIP/сервера. Затем отправьте на модерацию. Если она нашла проблему — исправьте и повторите затронутые проверки, обновив черновик.

5. После выпуска

  • Проверить опубликованную карточку, гостевой вход, рекламу и облачный ангар с реального устройства. Отследить ошибки WSS, задержки, CPU/RAM, место на диске и время ответа.
  • Проверить реальные оплаты в разрешённом платформой режиме, поступление отчётности и соответствие каталога. Не ждать выпуска, чтобы впервые проверить начисление и восстановление.
  • Ежедневно проверять резервные копии и необработанные оплаты; регулярно проверять восстановление. Обновления выпускаются новым ZIP и совместимой серверной версией с сохранением профилей и SKU.
  • Изучать удержание, прохождение боссов, рекламные показы и отзывы. Корректировать частоту рекламы и баланс по данным. Rewarded, новые переводы, sticky и новые платформы — отдельные проверенные обновления.
